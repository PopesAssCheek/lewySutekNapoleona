--- OPIS ZADANIA ---

Stwórz aplikację WPF, która:
  1. Pozwala użytkownikowi wpisać dowolny napis (tekst).
  2. Po kliknięciu przycisku znajduje dominującą literę w napisie,
     tzn. literę która pojawia się najczęściej.
  3. Jeśli kilka liter ma tę samą najwyższą liczbę wystąpień,
     wypisuje wszystkie — tak jak dominanta w zbiorze liczb.

  Przykład 1: "ala ma kota"
    a: 4, l: 1, m: 1, k: 1, o: 1, t: 1
    Dominanta: a (4 wystąpienia)

  Przykład 2: "abbc"
    a: 1, b: 2, c: 1
    Dominanta: b (2 wystąpienia)

  Przykład 3: "aabb"
    a: 2, b: 2
    Dominanta: a, b (po 2 wystąpienia)

  Uwagi:
    - spacje i znaki interpunkcyjne pomijamy, liczymy tylko litery
    - wielkość liter ignorujemy (A = a)

--- WYMAGANIA FUNKCJONALNE ---

  Zaimplementuj metodę:
    List<char> ZnajdzDominante(string tekst)

  Metoda powinna:
    - zliczyć wystąpienia każdej litery (ignorując wielkość liter)
    - znaleźć maksymalną liczbę wystąpień
    - zwrócić listę wszystkich liter które tę liczbę osiągają
    - zwrócić pustą listę jeśli tekst jest pusty lub nie zawiera liter

--- WYMAGANIA UI ---

  Układ okna: wszystkie GroupBoxy umieść wewnątrz jednego nadrzędnego GroupBoxa
  który obejmuje całą zawartość okna.

  Podział na GroupBoxy:

  GroupBox "Dane wejściowe":
    - pole TextBox na wpisanie napisu (wieloliniowe, min. 3 linie)
    - przycisk "Szukaj dominanty" z kolorowym tłem

  GroupBox "Wynik":
    - TextBlock lub Label wyświetlający dominującą literę/litery
    - TextBlock wyświetlający liczbę wystąpień

  GroupBox "Statystyki":
    - TextBlock wyświetlający pełne zliczenie wszystkich liter
      w formacie: a: 4, b: 2, c: 1 ...
    - posortowane alfabetycznie

  Kolory — zdefiniuj w App.xaml lub bezpośrednio:
    Tło okna:       #1A1A2E
    Tło GroupBoxów: #16213E
    Przycisk:       #E94560
    Tekst:          #EAEAEA

  Stringi wpisuj przez właściwość Content/Text w XAML,
  nie hardcoduj ich w code-behind.

--- WALIDACJA ---

  1. Puste pole tekstowe
       → wyświetl w GroupBox "Wynik": "Wpisz tekst"

  2. Tekst nie zawiera żadnej litery (same cyfry, znaki itp.)
       → wyświetl: "Brak liter w tekście"

--- WYMAGANIA TESTOWE ---

  Napisz testy jednostkowe (MSTest lub xUnit) dla metody ZnajdzDominante:

  PRZYPADKI POPRAWNE:
    - "ala ma kota"  → wynik zawiera tylko 'a'
    - "aabb"         → wynik zawiera 'a' i 'b' (obie dominanty)
    - "AAABBC"       → wynik zawiera tylko 'a' (ignorowanie wielkości)

  PRZYPADKI BRZEGOWE:
    - "abc"          → wynik zawiera 'a', 'b', 'c' (wszystkie po 1)
    - "   !!!   "    → wynik pusty (brak liter)
    - "a"            → wynik zawiera tylko 'a'

  PRZYPADKI NIEPOPRAWNE:
    - ""             → wynik pusty (pusty string)
    - null           → wynik pusty (zabezpiecz metodę przed null)

  Oddaj katalog z plikami źródłowymi projektu (bez folderu bin/ i obj/).
  Screenshoty:

    b) wyniki testów (wszystkie zielone)
    c) git log --oneline (po wykonaniu wszystkich kroków poniżej)

  Git — wykonaj kolejno:

    1. Zainicjuj repozytorium:
         git init

    2. Dodaj pliki i zrób pierwszy commit (gotowy UI + metoda):
         git add .
         git commit -m "opisowa wiadomosc np. dodano UI i metode ZnajdzDominante"

    3. Utwórz branch do testów:
         git branch testy
         git checkout testy

    4. Napisz testy, dodaj je i zrób commit na branchu:
         git add .
         git commit -m "opisowa wiadomosc np. dodano testy NUnit dla ZnajdzDominante"

    5. Wróć na główną gałąź i zmerguj:
         git checkout master
         git merge --no-ff testy

       Flaga --no-ff wymusza stworzenie osobnego commita merge.
       Bez niej git "przesunąłby" mastera do przodu po cichu
       i w logu nie byłoby śladu po branchu. Z --no-ff w logu
       zobaczysz 3 wpisy: commit przed branchem, commit z testami w branchu, commit merge.

    6. Zrób screena z:
         git log --oneline
